## I1 [medium] non-integer probe timeouts skip the kill — plugins/codex/scripts/session-lifecycle-hook.mjs (~145 worker probes, ~314 broker teardown)
`remaining/2` and `stepBudget(...)/2` can be fractional (e.g. 500.5); `spawnSync` rejects a non-integer `timeout` with ERR_OUT_OF_RANGE, the catch logs `kill-failed`, and the live worker is kept.
Fix: `Math.floor(...)` at both sites; additionally harden `runCommand` in lib/process.mjs: `timeout: Number.isFinite(options.timeoutMs) ? Math.max(1, Math.floor(options.timeoutMs)) : undefined` so no caller can ever pass a fractional or zero timeout (0 would mean unbounded). Tests: unit test in tests/process.test.mjs that `runCommand` passes an integer ≥1 timeout to the injected spawn (or asserts no throw with `timeoutMs: 500.5` on a real `node -e ""`); a hook test with `CODEX_COMPANION_SESSION_END_BUDGET_MS=1001` (odd) and one foreground job whose kill is delivered → record removed, no `kill-failed` on stderr.

## I2 [medium] Linux zombies are never reaped — lib/process.mjs processCommandLine linux branch (~76-80) and the reaper's legacy rule
A dead legacy worker that stays a zombie has an empty `/proc/<pid>/cmdline`; that now returns null (unknown) while `isPidAlive` is true, so the record is kept forever and the thread stays "in use". Before H2, `ps` returned `[node] <defunct>` which the rule reaped.
Fix: in the linux branch, when the cmdline is empty, read `/proc/<pid>/stat` (same `readFileSyncImpl`) and take the state field (first char after the last `)`, skipping the space); if it is `Z` (or `X`), return the sentinel string `"<defunct>"` — no `codex-companion.mjs` marker, so the reaper's existing rule reconciles the job as dead without signalling; any other state or an unreadable stat → null (unknown, conservative). Also export a tiny `isZombie(pid, { readFileSyncImpl, platform })` only if it makes the code clearer; otherwise keep it inside `processCommandLine`. Tests (tests/process.test.mjs, platform "linux" with injected `readFileSyncImpl`): empty cmdline + stat state `Z` → `"<defunct>"`; empty cmdline + state `S` → null; empty cmdline + stat throws → null. Reaper test (tests/tracked-jobs.test.mjs): legacy running job, `processCommandLineImpl: () => "<defunct>"` → failed with the "unrelated process"/dead message.
